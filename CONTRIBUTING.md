# Contributing to ForgeKiln

Thanks for taking an interest in ForgeKiln.

ForgeKiln is an early-stage learning and development project. Its structure and APIs may change frequently, so please keep contributions focused and explain the reasoning behind significant changes.

## Before you start

1. Check existing issues and pull requests to avoid duplicating work.
2. For substantial changes, open an issue or discussion first so the direction can be agreed on.
3. Keep changes focused. A small pull request is easier to review than a collection of unrelated changes.

## Reporting bugs

When reporting a bug, include:
- What you expected to happen.
- What actually happened.
- Steps to reproduce the issue.
- Your operating system, compiler, and relevant versions.
- Any useful error messages or build output.

## Submitting a change

1. Fork the repository and create a branch for your change.
2. Make the smallest coherent change that addresses the issue.
3. Build and test your changes locally.
4. Explain what changed and why in your pull request.
5. Mention any known limitations or follow-up work.

## Code guidelines

- Prefer clear, descriptive names.
- Keep functions and classes focused on one responsibility.
- Avoid adding dependencies without explaining why they are needed.
- Follow the existing style where practical.
- Include comments when they clarify intent or non-obvious decisions, not merely restate the code.
- Do not include generated binaries, IDE caches, credentials, or unrelated formatting changes.

## Discussion and review

Be respectful and constructive. Reviews should focus on the code and its impact, not on the person who wrote it. Maintainers may request changes, ask questions, or decline a contribution that does not fit the project's current direction.

## Licensing

By submitting a contribution, you agree that it may be reviewed and that you have the right to submit it. The project's contribution and licensing terms will be finalized in the repository's LICENSE file. Do not submit code that you do not have permission to contribute.
